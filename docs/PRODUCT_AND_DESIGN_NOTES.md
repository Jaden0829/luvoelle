# 产品与设计落地说明

## 从 Bob 调研中保留的产品骨架

Luvoelle 没有把翻译模型当作产品本身。核心链路被固定为：

```text
全局快捷键
→ 全屏框选
→ 本地 OCR
→ 可替换翻译 Provider
→ 鼠标附近浮窗
→ 一键复制
```

第一版刻意没有开发公开插件系统、划词替换、连续字幕和原图回填。这些功能会显著扩大权限、兼容性和排版复杂度，却不会优先改善截图翻译的基础体验。

OCR 结果从第一版开始保留行级结构：文字、置信度、矩形坐标、行 ID、段落 ID和检测语言。它们已经被用于工作台中的识别框显示，并为后续逐段复制、原图回填和多栏排序保留接口。

识别结果被定义为可校正草稿。用户直接点击主工作台或结果浮窗中的原文即可进入编辑，只有编辑状态才出现“取消 / 保存”操作：翻译模式保存后会重新调用当前翻译 Provider，并覆盖同一条历史记录；纯 OCR 模式保存后会更新历史并把修正文字重新复制到剪贴板。修正后原 OCR 坐标会失效，因此结果会清空旧文字框，避免展示与文本不一致的定位信息。

截图蒙层在应用启动后预热，此后重复复用同一组多显示器窗口。为减少 Windows 偶尔重新分配全屏合成表面的长尾，窗口不再隐藏，而是常驻为 0 透明度、不可聚焦、鼠标穿透状态；截图时只切换透明度和输入属性。透明窗口长期处于后台时，Chromium 默认可能降低定时器与渲染调度优先级，因此截图层同时显式关闭 `backgroundThrottling`，避免静置后重新唤醒出现秒级长尾。它又被拆成“即时交互层”和“后台冻结图”：透明交互层先覆盖屏幕，用户可立即移动和框选；受内容保护的蒙层不会进入桌面捕获，冻结图到达后再无感替换实时桌面。如果用户在冻结完成前松开鼠标，选区会被保留并在图像到达后自动裁剪。0.6.0 开发版回归中，截图层静置 3.2 秒后的三次可见延迟为 35ms、33ms、24ms，主进程入口为 18ms、18ms、6ms。截图期间同时使用系统级 `Escape`、窗口输入拦截和渲染层按键处理，确保焦点位于不同应用或不同显示器时仍可退出。

截图完成后结果浮窗主动获得键盘焦点，并支持 `Escape` 关闭。为保护 OCR 校对内容，编辑原文时第一次 `Escape` 只撤销未保存修改并退出编辑状态，第二次 `Escape` 才关闭结果浮窗。

翻译结果浮窗中的原文与译文采用互斥折叠布局。折叠译文时，其正文收起但保留标题与展开箭头，原文区域向下占满剩余空间；折叠原文时，译文向上扩展。两侧不能同时折叠，避免产生没有可读内容的空窗口；纯中文取字和纯 OCR 单栏模式不显示折叠按钮。

0.8.0 在截图识别结果中增加“编辑图片”入口，并以独立窗口承载标注工作流，避免挤压 OCR 阅读浮窗。编辑器保留截图的原始像素尺寸，显示时只做等比例适配；支持矩形、椭圆、箭头、自由画笔、文字和马赛克，提供颜色、线宽、文字字号、马赛克画笔大小与模糊度设置，并包含撤销、重做、复制编辑结果、保存 PNG 和完成并复制。马赛克通过可调像素块对涂抹路径建立遮罩，未涂抹区域不会被重新采样。

0.8.1 为马赛克增加圆形与方形画笔。圆形模式使用圆角连续路径遮罩；方形模式沿拖动轨迹插值铺设轴对齐方块，避免快速拖动时出现空隙。画笔形状被保存在每条马赛克标注中，因此同一图片可以混用两种形状，撤销、重做和导出也会准确恢复原选择。

0.9.0 根据真实操作反馈重新定义马赛克的三种模式：选择马赛克工具时默认进入方形框选，按下并自由拖拽确定矩形范围；圆形模式以相同方式确定椭圆范围；只有笔刷模式才按照指针轨迹连续涂抹，并显示画笔大小参数。三种模式都保留独立模糊度，且每条标注记录自己的模式。结果浮窗的折叠热区也从小箭头扩展为整条原文/译文标题栏，复制、保存、编辑等按钮仍保持独立点击，不会误触折叠。

0.9.1 将结果浮窗左下角改为剪贴板状态区。截图进入处理时显示“截图已复制”；点击原文、译文或主复制按钮后分别显示“原文已复制”或“译文已复制”。旁边常驻“复制截图”操作，直接使用当前任务内存中的原截图重新写入系统剪贴板，因此文字复制覆盖图片后无需进入编辑器即可恢复。状态只在实际剪贴板写入成功后更新，写入失败会保留原状态并提示重试。

0.9.2 为方形和圆形马赛克增加持久选区反馈：拖动时绘制一条带深色衬底的低对比度白色虚线，松开后继续显示当前选区；模糊度滑杆直接修改所选马赛克标注的像素块尺寸并实时重绘。撤销或重做会同步恢复对应标注的形状按钮与选区。复制、保存和“完成并复制”会先执行一次无辅助线渲染，取得 PNG 后再恢复编辑视图，因此选区虚线不会进入输出图片。

0.10.0 将同一套“完成后继续调整”原则扩展到矩形、椭圆和箭头：新建标注保持选中并显示淡蓝虚线边界，上方线宽与颜色控件会实时写回该标注，而不是只影响下一次绘制；调整不会改变几何范围。输出图片继续使用无辅助线渲染。结果浮窗同时移除底部重复的“复制译文”主按钮，保留内容区内与语义对象直接对应的复制入口；页脚只承担剪贴板状态、恢复截图和编辑图片。翻译失败时译文标题栏将复制替换为“重试”，成功后恢复复制，并清除失败态红色进度条。

0.11.0 将产品品牌、窗口标题、托盘文案、应用 ID、安装包、截图默认文件名、渲染层桥接命名、测试和交付文档统一更新为 Luvoelle。启动时会尝试从旧版开发配置目录迁移 `state.json`，确保现有设置和历史记录在品牌切换后继续可用。

0.12.0 增加独立“视觉拆解”结果窗与 `Alt + P` 截图入口。视觉模型输出被固定为可校验结构：商品、材质、颜色、形态、细节、构图、镜头、灯光、背景、道具、色板、画面文字、字体、风险与六类提示词。提示词默认可编辑、切换目标模型并复制；具体品牌、Logo、水印和文案被拆出，用变量替代；无法确认的镜头参数必须标记为推测。OCR 与视觉模型并行运行，OCR 结果只用于补充 `visibleText`，不会阻塞模型理解。历史记录保存结构化结果，不保存源图。

0.13.0 将视觉能力实现为可替换的 OpenAI-compatible `/chat/completions` Provider。默认配置面向本机 `http://127.0.0.1:8080/v1` 的 Qwen3-VL 服务，同时允许云端端点和系统加密 API Key。设置页提供 `/models` 连通性检测，但不捆绑大体积模型权重。推荐把 Apache 2.0 的 Qwen3-VL 作为商业默认方向；JoyCaption 仅借鉴提示词组织方式，不把权重作为默认分发内容；有 GPL 或非商用权重限制的项目只用于研究，不进入闭源客户端。

0.14.0 在视觉结果窗增加参考生成，复用兼容 `POST /images/edits` 的服务。三种策略分别约束风格特征、构图关系和自有商品外观；所有策略都要求避免复制竞品水印、品牌、版权角色与不可替换文案。“保持商品”在界面和主进程双重校验素材权利确认，不能通过直接 IPC 绕过。生成结果可复制或保存，源图和生成图均不写入历史。

0.14.1 修复视觉 Provider 首次配置时的保存认知问题。“检测服务”原本只读取当前输入进行临时连通性测试，不会持久化，而全局保存按钮位于长设置页末尾，容易让用户误以为检测成功即完成配置。现在按钮改为“检测并保存”，只有 `/models` 检测成功后才通过 `safeStorage` 保存视觉 Key；设置页右下角始终显示固定保存栏，输入变化会切换为“有未保存的更改”。视觉任务在 OCR 完成但模型仍运行时显示“文字已提取，正在等待视觉模型”，连接失败会显示具体端点和“检测并保存”指引。

0.14.2 将视觉结果窗改为严格的单任务状态机。收到新截图时会在同一渲染帧内清空上一张图的结构化字段、色板、风险、全部提示词和生成结果，切回视觉拆解页，并在分析完成前禁用提示词标签与生成操作。进度、完成、失败和参考生成事件都携带或校验当前任务 ID；旧请求晚于新请求返回时会被静默丢弃，不能覆盖新图。用户主动打开历史记录则显式创建一次新的任务切换，不会被迟到事件保护误伤。

0.14.3 重新梳理提示词模板与生成 Provider 的信息层级。通用中文、英文、Qwen-Image、FLUX 和 Midjourney 只是可编辑文本模板，不承担模型路由；实际生成始终调用设置页“参考生成”中的 endpoint 与 model。结果窗现在在生成卡片和加载遮罩中直接显示实际模型与本地网关地址。主提示词复制操作从低对比度页脚移到编辑器右上角，并改成带图标的蓝色操作。重新生成会先清空旧图片和完成元数据，隐藏复制/保存按钮；成功后才恢复，失败则显示独立错误，不再出现“正在生成”与“参考生成完成”并存。

0.14.4 修正视觉模型设置的状态语义。输入框和主状态现在始终显示真正写入配置的模型；Cockpit Tools 或其他 OpenAI-compatible 服务的 `/models` 返回值被收进独立的“服务返回的模型”详情，不再冒充当前模型。当前名称不在目录中时显示黄色提醒，说明配置已经按输入保存，但实际可用性尚未由目录确认。视觉拆解结果窗补齐最大化/还原控制，并同步原生 BrowserWindow 状态；按钮、双击标题栏和系统窗口状态使用同一套反馈。

0.14.5 将“生图提示词”从等待期禁用标签改为可进入的过程页面。新视觉任务仍会立即清空上一张图的提示词，保证任务隔离，但用户在模型处理期间可以主动切换过去，看到图片提交、视觉拆解、提示词就绪三阶段反馈。OCR 完成但视觉模型仍运行时会说明两者职责和当前状态；分析完成后等待卡片原地替换为可编辑提示词，不强制跳回其他标签。失败时保留可进入的错误说明，并提供返回视觉拆解入口。

0.15.1 将旧有的通用截图框图标替换为 Luvoelle Prism。两个错位的开放棱镜分别代表原始画面与理解后的信息层，中心四向光点对应 OCR、翻译、视觉拆解与提示词生成汇聚到“理解”这一结果。深墨蓝背景建立稳定的轻奢底色，白色与电光青紫在极小尺寸下仍保持高对比。Logo 使用单一 SVG 母版，通过 `npm run build:icons` 离屏渲染为 512px PNG 和包含 16、24、32、48、64、128、256px 图层的 Windows ICO，避免主界面、托盘与安装包出现版本不一致。

0.15.2 在第二轮品牌评审后采用 Folded L 替换 Prism。宽体 L 直接绑定 Luvoelle 名称，底部朱红折面把“截图画面翻折为可阅读、可翻译信息”压缩成一个记忆钩子；深紫红底、瓷白主体与朱红折面在 16px 下仍能形成三个清晰色块。工作台、截图结果浮窗和视觉拆解窗口不再各自维护内联 SVG，而是统一引用 `assets/icon.svg`；PNG、七尺寸 ICO、任务栏、托盘与安装包继续从这一母版自动生成。

0.16.0 将本地 OCR 主链路升级为 PP-OCRv6 small 的检测与识别 ONNX 模型，并放到 Node `worker_threads` 独立线程运行。相比浏览器 WebGPU/WASM 试验链路，原生 ONNX 热态延迟更稳定且不会占用渲染线程；模型在应用启动后后台初始化和预热，截图 UI 不等待模型启动。识别默认保留原图尺度与低面积文本框，只有整体低置信、较小文字或明显异常字符时，才由主进程用 `nativeImage` 放大原图进行第二遍识别，并按文字框重叠度合并更可靠结果。Tesseract 继续作为完全离线的故障回退，避免原生模块或模型资源异常时失去取字能力。浏览器 OCR host、WebAssembly runtime 和重复模型压缩包已移除，安装包只携带原生 Worker、ONNX 模型与必要运行时。

同一版本修正结果浮窗的窗口轮廓：透明 BrowserWindow 不再为自绘阴影预留矩形 padding，根页面与主体共同使用 24px 圆角裁切，并由系统窗口阴影承接层次。这样四个角的透明像素从窗口边缘开始，消除了“外层灰色直角、内层白色圆弧”的双重轮廓。

0.16.1 重新划分结果浮窗的 Provider 信息层级。OCR 引擎和识别置信度属于整张截图的提取阶段，因此保留在顶部任务状态；GPT 模型或 Google Translate 属于译文结果，因此以紧凑标签放在“译文”标题旁。自动选择、自动回退等完整路由信息写入标签提示，默认只露出最终实际模型名称，避免顶部把翻译模型与 OCR 引擎拼成一串而造成归属误解。编辑原文重译或手动重试后，标签会跟随新结果刷新；折叠译文时仍保留模型标签，方便快速确认来源。

0.16.2 将矩形、椭圆和箭头的编辑反馈改为严格的所画即所得。完成标注后不再绘制淡蓝色虚线包围框，避免辅助视觉与最终图片混在一起；最近完成的矢量标注索引仍保留，线宽和颜色控件继续实时写回该标注。方形与圆形马赛克的虚线边界承担模糊区域范围提示，仍按原交互保留，并继续在复制、保存和导出时自动隐藏。

0.16.3 将 OCR 技术实现与用户阅读信息分层。本地引擎型号、原生运行后端和兼容回退名称不再出现在结果浮窗、工作台进度与设置说明中；用户只看到识别置信度、小字增强、AI 校正和中文跳过翻译等可用于决策的信息，实际 Provider 仍保留在历史数据和诊断字段中。结果浮窗右上角新增阅读尺寸控制：初始点击会根据当前工作区居中放大，最大控制在约 960 × 860 px，再点击进入系统最大化，下一次点击回到之前的适度尺寸，此后在两者之间循环。新截图和关闭重开会回到初始鼠标附近尺寸；适度放大或最大化期间，OCR 进度与中文紧凑布局不会抢回窗口大小。

0.16.4 将自动翻译路由从 220/120 字阈值下调为 110/60 字：文本达到 110 字直接走上下文模型；达到 60 字且包含至少两个完整句子也走上下文模型；4 个非空行、项目列表、编号列表、制表符或连续三个空格仍被视为结构化内容并走上下文模型，其余内容优先 Google。句子统计把中文 `。！？` 与后接空白或结尾的英文 `.?!` 分开计算，既支持中文连续书写，也避免把 `gpt-5.4-mini` 这类模型名中的句点误判为句末。自动模式下的双向失败回退逻辑保持不变。

0.15.0 将文字处理重构为可组合路由。OCR 提供极速本地、自动增强、GPT 精确识别三档：所有模式先运行本地 Tesseract；自动模式仅在整体置信度低于 82%、低置信行比例较高、结果为空或包含明显异常字符时调用视觉模型；精确模式固定调用。AI 请求使用原图细节并要求逐字 JSON 转写，不翻译、不润色；等待期间先展示本地文字，AI 完成后原地更新，失败则保留本地结果并显示回退来源。翻译服务提供 Google 极速、GPT 上下文和自动选择：自动模式把长文、多行、列表和表格交给 GPT，短句走 Google，并在一条路线失败时尝试另一条。设置页提供一键复用视觉服务配置，端点、模型和加密密钥只在主进程中安全复制，不暴露给渲染页面。

0.6.1 将托盘图标从运行时 SVG 转换改为 Windows 原生多尺寸 ICO。资源内包含 16、24、32、48、64、128、256px 表示，由 Windows 根据任务栏 DPI 直接选取，避免 SVG 经 `nativeImage.resize()` 后偶发生成空白托盘图标。

框选完成后，裁剪图片会先写入系统剪贴板，再开始 OCR 与翻译。针对 Windows 剪贴板被其他程序短暂占用时 Electron 可能静默写入失败的情况，0.6.0 增加了写入后读取校验与渐进短间隔重试，并把真实写入结果传给浮窗状态。纯 OCR 模式识别完成时使用多格式剪贴板，同时写入图片与识别文字，支持图片编辑器粘贴图像、文本编辑器粘贴文字。

截图翻译在 OCR 完成后执行语言路由：含有至少一个有效英文词的内容进入翻译；有中文且没有有效英文词时判定为纯中文，跳过翻译并将结果浮窗压缩到 340–540px 的自适应高度。编辑原文后会重新执行同一语言判断，因此加入英文会自动展开翻译，改回纯中文则再次折叠。

底层调研依据：Electron 官方说明 `desktopCapturer.getSources()` 会处理屏幕源缩略图；Windows Desktop Duplication API 则把桌面帧放在 GPU 内存并支持持续帧与脏区域元数据，适合下一阶段的常驻原生捕获助手；GDI `BitBlt` 是更直接的位块拷贝备用路径。

## 从 Apple 首页提炼的界面规则

本项目通过 Playwright 分别以 1440 × 1000 与 390 × 844 视口访问 Apple 首页，采集了 DOM、计算样式、颜色、响应式断点、动画时长和全页截图。观察结果包括：

- 正文基色为 `#1d1d1f`，页面大量使用 `#f5f5f7` 与白色；
- 固定导航是约 80% 白色叠加 `saturate(1.8) blur(20px)`；
- 桌面与移动导航在约 833/834px 处切换；
- 标题使用高字重、紧字距和短行宽；
- CTA 以蓝色胶囊按钮为主，次操作保持克制；
- 页面以大尺寸完整视觉区块为主要节奏，区块间只用窄灰白间隔；
- 导航子项常见 240ms 与 320ms 过渡；
- 移动端不是简单缩放，而是重新安排导航、字号、图像和内容高度。

Luvoelle 将这些规律映射到桌面工具：

| Apple 方法 | Luvoelle 落地 |
| --- | --- |
| 半透明固定导航 | 固定侧栏、标题栏与 acrylic 结果浮窗 |
| 大标题 + 短说明 | 工作台首屏一句话解释任务 |
| 单一蓝色主 CTA | 截图翻译、选择图片、复制译文 |
| 大型内容区块 | 截图翻译、OCR、视觉拆解三张主任务卡 |
| 视觉先于细节 | 先显示截图，再逐步补全原文和译文 |
| 响应式重排 | 窄窗口压缩侧栏、历史卡片与导入操作 |
| 克制动效 | 180–320ms 位移、透明度、状态过渡 |

## 当前 Provider 边界

### OCR

默认引擎加载随应用分发的 PP-OCRv6 small 检测、识别 ONNX 模型与中英文字符字典，通过原生 ONNX Runtime 在独立 Worker 中执行；`eng` 与 `chi_sim` Tesseract 模型仅在主引擎失败时接管。两条路径输出统一为文字、置信度、矩形坐标、行 ID、段落 ID和检测语言，工作台和结果浮窗无需感知底层切换。

### 翻译

当前支持：

1. Google 公共翻译端点，用于开箱体验；
2. OpenAI 兼容 `/chat/completions` 接口，可连接 OpenAI、Azure 兼容网关、Ollama、LM Studio 或其他兼容服务。

密钥不会出现在渲染进程、日志和历史记录中。

### 视觉理解

`VisionProvider` 使用多模态 `/chat/completions`，把图片作为 `image_url` data URL 发送。默认模型名称为 `Qwen3-VL-4B-Instruct`，但客户端不假设某一种推理运行时；llama.cpp、vLLM、LM Studio 或自建网关只要实现兼容协议即可接入。远程端点没有 API Key 时会拒绝分析，本机回环地址允许无密钥连接。

### 参考生成

`GenerationProvider` 使用 multipart `POST /images/edits`，支持服务返回 `b64_json`、data URL 或临时 URL。客户端不内置 IP-Adapter、ControlNet、SAM 2 或商品修复模型；这些能力可以在服务端工作流中组合。客户端只传递经过用户编辑的提示词、参考图和策略约束，避免把特定模型实现锁死在桌面端。
