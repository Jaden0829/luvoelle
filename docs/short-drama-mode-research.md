# 短剧视觉拆解与反推提示词调研

本轮调研的目标不是寻找一套可直接复制的“万能提示词”，而是确认短剧截图应如何被拆成稳定、可编辑、可继续生成的影视数据。结论是：短剧必须使用独立的影视数据契约，不能复用电商主体、卖点和商品生图模板。

## 落地的数据结构

短剧模式现在独立输出：

- 剧情节拍与戏剧目的；
- 角色外观、服装、表情、身体语言和画面位置；
- 人物关系、场景时空、剧情道具；
- 可见动作、表演情绪、冲突张力、空间走位；
- 身份、服装、场景、人物朝向和画面轴线连续性；
- 前镜承接、后镜建议、建议时长与无法确认的信息；
- 首帧中文、首帧英文、关键帧、分镜复现、图生视频运动、角色连续性和负面提示词。

## 隔离原则

1. 日常、电商、短剧分别使用独立 JSON schema 和 system instruction。
2. 短剧模式不读取通用电商提示词字段；即使兼容服务返回旧字段，也不会进入短剧提示词选择器。
3. 单帧无法证明的剧情、关系和前因后果必须标记为“推测”。
4. 图生视频提示词把输入图视作首帧，只描述接下来的动作变化、环境动态和一个明确运镜。
5. 短剧参考生成策略为“保持角色 / 保持镜头 / 延续剧情”，不再复用商品保持策略。
6. 归一化层保留最后一道语义防线，拦截旧服务返回的营销模板污染；可见文字仍按原图如实列出。

## 回归边界

自动化测试会检查短剧模式的提示词、摘要和参考生成请求不得包含旧的商品占位符、商品展示、商业主图、商品保持和商品瑕疵描述；同时继续验证三模式缓存、编辑内容恢复、清除当前模式重生以及电商九宫格不受影响。
